# Утилиты

Фронтенд на React + TypeScript + Vite со страницей «Утилиты» и бэкенд на Java Spring Boot + PostgreSQL для покер-планирования.

1. **Покер планирование** — онлайн-комнаты по ссылке. Роли: **участник** (голосует картами) и **зритель** (видит ход голосования и результаты, но не голосует; может вскрывать карты и начинать новый раунд — удобно для PO или скрам-мастера). Роль можно сменить прямо в комнате. Колоды: Фибоначчи, модифицированный Фибоначчи, размеры футболок, степени двойки. Голоса скрыты на сервере до вскрытия. Есть статистика (среднее, медиана, мин/макс, распределение), отметка консенсуса, история оценок и статус «в сети». Состояние комнаты обновляется у всех в реальном времени через SSE.
2. **Конвертер Base64** — кодирование и декодирование с поддержкой UTF-8, режим URL-safe, перевод файла в Base64.
3. **JSON валидатор и форматтер** — проверка с указанием строки и столбца ошибки, расстановка переносов строк и отступов, сортировка ключей, минификация.

## Быстрый запуск через Docker

```bash
docker compose up --build
```

Приложение откроется на http://localhost:8000. Nginx отдаёт фронтенд и проксирует `/api` в бэкенд.

## Разработка

```bash
# 1. PostgreSQL (или свой: база poker, пользователь и пароль poker)
docker compose up -d db

# 2. Бэкенд на :8080 (Java 21)
cd backend && mvn spring-boot:run

# 3. Фронтенд на :5173, /api проксируется на :8080
npm install
npm run dev
```

Проверки: `npm run lint`, `npm run build`, `cd backend && mvn test`. Тестам нужен PostgreSQL с базой `poker_test`: `createdb -O poker poker_test` или `TEST_DB_URL=...`.

### Настройки бэкенда (переменные окружения)

| Переменная     | По умолчанию                              |
|----------------|-------------------------------------------|
| `DB_URL`       | `jdbc:postgresql://localhost:5432/poker`  |
| `DB_USER`      | `poker`                                   |
| `DB_PASSWORD`  | `poker`                                   |
| `PORT`         | `8080`                                    |
| `CORS_ORIGINS` | `http://localhost:5173`                   |
| `ROOM_TTL`     | `30d` — неактивные комнаты удаляются      |

Схема БД создаётся миграциями Flyway (`backend/src/main/resources/db/migration`).

### API

| Метод    | Путь                                         | Описание                                    |
|----------|----------------------------------------------|---------------------------------------------|
| `GET`    | `/api/decks`                                 | Колоды                                      |
| `POST`   | `/api/rooms`                                 | Создать комнату `{deck}`                    |
| `GET`    | `/api/rooms/{id}`                            | Состояние комнаты                           |
| `PATCH`  | `/api/rooms/{id}`                            | Изменить `{story, deck}`                    |
| `POST`   | `/api/rooms/{id}/participants`               | Войти `{name, role: VOTER\|SPECTATOR}` → токен |
| `PATCH`  | `/api/rooms/{id}/participants/me`            | Сменить имя или роль                        |
| `DELETE` | `/api/rooms/{id}/participants/{pid}`         | Удалить участника или выйти                 |
| `PUT`    | `/api/rooms/{id}/vote`                       | Голос `{card}` (`null` — снять)             |
| `POST`   | `/api/rooms/{id}/reveal`                     | Вскрыть карты                               |
| `POST`   | `/api/rooms/{id}/reset`                      | Новый раунд `{save}`                        |
| `DELETE` | `/api/rooms/{id}/history`                    | Очистить историю                            |
| `GET`    | `/api/rooms/{id}/events?token=`              | SSE-поток состояния комнаты                 |

Действия от имени участника требуют заголовок `X-Participant-Token`. Токен выдаётся при входе и хранится в `localStorage` браузера.

Ограничение: SSE-подписки хранятся в памяти процесса, поэтому бэкенд рассчитан на один экземпляр. Для нескольких экземпляров нужна общая шина событий, например PostgreSQL `LISTEN/NOTIFY`.
